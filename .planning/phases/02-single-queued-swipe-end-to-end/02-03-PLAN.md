<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Extension ↔ ST backend proxy (network) | `sendOpenAIRequest`/`fetch` cross this boundary; request headers (incl. any API key the proxy attaches) flow through `getRequestHeaders()` |
| Extension's own `AbortController` ↔ ST's global single-flight state | The dry-run `Generate` call replaces ST's module-private `abortController`/`generation_started` unconditionally at its top (ARCHITECTURE.md §2.3) — only safe because capture only ever runs while idle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|------------------|
| T-02-03-01 | Information Disclosure | `src/adapter.js` (`send()`) | mitigate | Never logs `captured`/request body/response to console; errors are normalized to the 3-category taxonomy (`api`/`empty`/`cancelled`) before leaving the adapter, so no raw backend error text or header values ever reach the Runner/UI layer |
| T-02-03-02 | Tampering | `src/adapter.js` (`capture()` vs. native single-flight state) | mitigate | Idle-gate checked immediately before every `Generate('swipe', {signal}, true)` call; `{signal}` always passed (SPIKE-REPORT.md criterion d — the no-signal condition was only verified once, so the with-signal path is mandatory, not optional) |
| T-02-03-03 | Repudiation | `src/adapter.js` (`isSuccessful`) | mitigate | GEN-06: success is defined as a non-empty, non-aborted text result, never "the promise resolved" — closes the exact failure mode RESEARCH.md Pitfall 5 describes (early exits resolving with nothing produced) |
| T-02-03-04 | Denial of Service | `send()` own `fetch`/`sendOpenAIRequest` call | accept | One item's failed/slow request only delays that one item (Runner continues to the next on error); no retry loop exists in Phase 2 that could amplify a single failure into repeated spend (SAFE-01 auto-retry-prevention is a Phase 4 requirement, not needed here because there is no retry at all yet) |

</threat_model>
