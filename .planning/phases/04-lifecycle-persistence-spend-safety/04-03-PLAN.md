<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| chat file (importable) to chatMetadata.queuedSwipes | Untrusted data read on load |
| extension to chat file | Queue written via ST save functions |
| old chat to new chat | In-memory queue must never bleed across chats |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering / DoS | crafted queuedSwipes blob | mitigate | loadStored: version check, per-field type validation, cap 20, 24h expiry, future-date skew limit, target hash match; never throws |
| T-04-11 | Tampering | queue persisted into wrong chat during switch | mitigate | persist bound to chatKey + integrity, refuses empty chat; chat-switch handler pauses and unbinds before rebinding |
| T-04-12 | Elevation (spend) | auto-run after refresh | mitigate | Load always pauses 'restored' before anything can start; no auto-resume path exists in this plan |
| T-04-13 | Information disclosure | prompts or text in exported chat | mitigate | serialize whitelist asserted by unit test; ids/timestamps/hashes/names/connection names only |
| T-04-14 | Tampering | late result from aborted item appended to new chat | mitigate | requeue disposition + epoch check + fingerprint 'chat' status + appender checks |
| T-04-15 | Information disclosure | hash of message text stored | accept | djb2 hash with length, non-reversible in practice for prose; needed for stale detection |
</threat_model>
