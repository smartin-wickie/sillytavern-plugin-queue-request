<objective>
## Phase Goal

**As a** SillyTavern user with the same chat open in two browser tabs, **I want** only one tab to run the queue, **so that** a second tab can never double-generate or overwrite the queue in my chat.

Purpose: SAFE-04 core (D-07 first tab wins, D-08 per-chat ownership, D-09 heartbeat about 2s and takeover after about 5s, D-10 demotion). Mechanism choice (Claude's discretion): a `localStorage` lease with `storage` events and a heartbeat; Web Locks rejected (secure contexts only, many ST installs are plain HTTP on a LAN); BroadcastChannel rejected as the authority (no persisted state). Takeover with an empty queue: the takeover toast is shown only when at least 1 item is held (researcher default). `localStorage` failure: fail open, run as owner (research A4 default).
Output: ownership module, owner gates in runner/store, lifecycle integration (claim, release, takeover, demotion), wiring, tests. Read-only rendering and the cross-tab state mirror come in plan 08.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-30 | Elevation (spend) | two tabs run one queue | mitigate | Lease + heartbeat read-back demotion (D-10) + owner check at start and pre-append + store read-only persist guard |
| T-04-31 | Elevation (spend) | auto-run after takeover | mitigate | Takeover always pauses 'takeover', never opens popup, never auto-resumes |
| T-04-32 | Spoofing | forged lease/state keys | mitigate | Parse in try/catch, validate shapes; worst case read-only (DoS on self) or wrong count display; queue of record is chat_metadata |

| T-04-35 | Denial of service | localStorage disabled locks the only tab out | accept | Fail open (run as owner); documented risk of two tabs in storage-less browsers |
