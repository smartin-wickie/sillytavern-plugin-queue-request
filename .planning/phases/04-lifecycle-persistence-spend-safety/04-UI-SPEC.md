# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by bm-ui-researcher, verified by bm-ui-checker.

**Context note:** This is the same project as Phases 2 and 3: a vanilla jQuery/ES-module SillyTavern (ST) UI extension, not a React, Next or Vite app. The shadcn gate does not apply. There is no `components.json` and no build step, and CLAUDE.md locks the project to ST's existing jQuery + template-HTML conventions. This contract **extends `03-UI-SPEC.md` and must not contradict it.** Every Phase 3 token, reservation and copy string stays as written unless this document says it changes.

Phase 4 adds no new surface type. It adds **states** and **messages** to the surfaces that already exist:
1. A paused state for the badge, cancel dropdown and progress bar, with a Resume action.
2. A read-only state for the control, badge, dropdown and progress bar in a second browser tab (SAFE-04).
3. Two confirm popups built on ST's own `callGenericPopup`: a resume/discard popup (PERS-02/03) and a connection-changed popup (SAFE-02).
4. A set of lifecycle and safety toasts that explain why items were cleared, dropped or paused (GUARD-02, PERS-04, SAFE-01, SAFE-03).

**No new settings field.** The circuit-breaker threshold input from Phase 3 (`#qs_circuit_breaker`, `circuitBreakerThreshold`) becomes enforced here (SAFE-01). Nothing else is added to `settings.html`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none. Not applicable: vanilla ST extension with no component registry and no build step |
| Preset | not applicable |
| Component library | none. Native DOM + jQuery, extending the Phase 3 classes (`.qs-queue-control`, `.qs-queue-badge`, `.qs-queue-dropdown*`, `.qs-progress-bar*`). Popups use ST's `callGenericPopup` + `POPUP_TYPE.CONFIRM` from `getContext()`. Do not use the deprecated `callPopup` or build a custom modal. Toasts use the page-global `toastr` |
| Icon library | Font Awesome Free, `fa-solid`, bundled by ST core. New icons this phase: `fa-pause` (paused indicator in the badge), `fa-play` (Resume button in the progress bar), `fa-lock` (read-only indicator in the badge in the second tab). All Phase 2/3 icons are reused unchanged: `fa-clock`, `fa-spinner fa-spin`, `fa-xmark`, `fa-stop` |
| Font | inherit. No font-family, size or weight override is introduced. Same binding rule as Phases 2 and 3 |

Source: `03-UI-SPEC.md` Design System (inherited); CLAUDE.md "Notifications and UI primitives" (`Popup`/`callGenericPopup` only for confirm dialogs, `toastr` with `preventDuplicates`).

## Spacing Scale

Inherited unchanged from `03-UI-SPEC.md`. Phase 4 declares no new token.

| Token | Value | Usage this phase |
|-------|-------|------------------|
| xs | 4px | Gap between the `fa-pause`/`fa-lock` icon and the count inside the badge (same slot the Phase 2 spinner already uses); gap between a paused-reason line and its icon in the dropdown |
| sm | 8px | Gap between the progress bar's Resume button and Stop button (the same `gap: 8px` `.qs-progress-bar` already declares); top margin of the dropdown's Resume button (same as the existing `.qs-dropdown-cancel-*` `margin-top: 8px`) |
| md | 16px | Dropdown outer padding and the gap between the header and the status line (existing `.qs-queue-dropdown` values) |
| lg | 24px | Not used this phase. No settings group is added |
| xl–3xl | 32/48/64px | Not used. Popups get their padding from ST's own popup CSS and must not be overridden |

Exceptions:
- **Resume button in the progress bar (`.qs-progress-bar-resume`)**: 25x25px, exactly matching `.qs-progress-bar-stop`. This is the same pixel-parity rule Phase 3 applied to icon controls.
- **Popup content**: plain `<p>` elements inside the popup body with no inline style, so ST's popup stylesheet controls the spacing.

## Typography

No new type scale. Every text node inherits its style from its DOM context. This rule is binding.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (popup body text, dropdown status line) | inherit (ST popup body / `.qs-queue-dropdown` context) | inherit (normal, 400) | inherit |
| Label (paused/read-only status line in the dropdown, progress-bar label) | inherit; the progress-bar label keeps Phase 3's existing `font-size: 12px` on `.qs-progress-bar-label` and gains no new size | inherit (normal, 400) | inherit |
| Heading (popup title, dropdown header) | inherit from ST's popup heading markup (`<h3>` in the popup content, which is ST's own convention) and from the existing `.qs-dropdown-header` (`font-weight: bold`) | inherit (bold, from existing markup) | inherit |
| Display | not applicable | — | — |

Exactly 2 weights are in use, both inherited: normal for body and label text, and bold for the dropdown header and popup `<h3>`. Toast text keeps toastr's default styling with no CSS override, as in Phases 2 and 3.

## Color

No hex values. Same binding rule as Phases 2 and 3: reuse ST theme variables, because a hardcoded hex breaks under user-selected themes. Every Phase 3 reservation stays as it is.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | inherit / no override | Popup body text, dropdown status lines, the badge's pause and lock icons |
| Secondary (30%) | Existing `.qs-queue-dropdown` surface (`var(--SmartThemeBlurTintColor)` background, `var(--SmartThemeBorderColor)` border). Popups use ST's own popup surface with no override | Dropdown in all states, including paused and read-only; both confirm popups |
| Accent (10%) | Existing `var(--SmartThemeQuoteColor)` on `.qs-progress-bar-fill` only | Still reserved for **the progress-bar fill only**. In the paused state the fill keeps the same variable at `opacity: 0.5` (modifier class `.qs-progress-bar--paused`). No new accent use is added. The Resume button does **not** get the accent color |
| Destructive | Existing `var(--crimson70a)` | Still reserved for cancel actions only: per-item ×, Cancel running, Cancel all, the wand menu's "Cancel all queued", and the progress-bar Stop. These are hidden in the read-only tab (see Interaction Contract). The popups' "Discard queue" button uses ST's default popup button styling, not crimson: in ST it is the popup's standard negative button, and the popup itself acts as the confirmation |

Accent reserved for: **the progress-bar fill only**. This is unchanged from Phase 3 and not extended to Resume, pause or lock icons, or popups.

Destructive reserved for: **cancel actions only**, unchanged from Phase 3. Resume (`fa-play`, dropdown "Resume queue") is neutral and uses `color: inherit` with the same transparent background and `1px solid var(--SmartThemeBorderColor)` border as the dropdown surface, so it does not look like a cancel button.

## Copywriting Contract

All strings are static literals. Interpolated values are numbers or ST-provided model, API or preset names, and they are inserted via `textContent` or the toastr message string. They are never written with `innerHTML`, and raw backend error text is never shown (Phase 2/3 rule).

### Primary CTA and popups

| Element | Copy |
|---------|------|
| Primary CTA (this phase) | `Resume queue`. Used as the OK button of the resume popup, the dropdown Resume button label, and the progress-bar Resume tooltip |
| Resume popup (PERS-02/03) title | `Resume queued swipes?` |
| Resume popup body | `{n} queued swipe(s) are saved for this chat.` plus a second line, `Queued with {model} ({api}).` If the stored model is unknown, the second line is `They will use your current connection.` |
| Resume popup buttons | OK: `Resume queue`. Cancel: `Discard queue` |
| Resume popup dismissed (Esc / close ×) | No toast. Items stay stored and the queue stays paused. The user can resume or cancel later from the badge |
| Resume popup after Discard | `toastr.info`: `Discarded {n} queued swipe(s).` |
| Connection-changed popup (SAFE-02) title | `Connection changed` |
| Connection-changed popup body | `These swipes were queued with {oldModel} ({oldApi}, preset {oldPreset}).` / `Now active: {newModel} ({newApi}, preset {newPreset}).` / `Continue with the current connection?` Only the fields that changed are listed; unchanged ones are omitted from both lines |
| Connection-changed popup buttons | OK: `Continue queue`. Cancel: `Keep paused` |
| Combined case (resume popup + connection changed on the same load) | One popup, never two in a row. Use the resume popup with an extra line, `Connection changed since queueing: now {newModel} ({newApi}).` OK `Resume queue` counts as consent for SAFE-02 |

### Lifecycle toasts (GUARD-02, GUARD-03, PERS-04)

| Trigger | Copy |
|---------|------|
| Target message edited | `toastr.info`: `Cleared {n} queued swipe(s): the message was edited.` |
| Target message deleted | `toastr.info`: `Cleared {n} queued swipe(s): the message was deleted.` |
| New user message sent | `toastr.info`: `Cleared {n} queued swipe(s): a new message was sent.` |
| `{n}` | Pending items plus a running item that was discarded as stale. If `n` is 0, no toast is shown |
| Chat switch (GUARD-03) | No toast when leaving. Pending items stay stored and the aborted running item is not reported as a failure. On return, the resume popup is the only feedback |
| Stale stored items dropped on load (PERS-04) | `toastr.info`: `Dropped {n} saved queued swipe(s): the message changed or they expired.` Shown once per chat load, before the resume popup. If every item was stale, no popup follows |

### Pause and safety toasts (SAFE-01, SAFE-03, SAFE-04, GUARD-06)

| Trigger | Copy |
|---------|------|
| N consecutive failures (SAFE-01) | `toastr.warning`: `Queue paused after {n} failures in a row. Check your connection, then resume from the queue badge.` No automatic retry |
| Connection changed (SAFE-02) | No toast. The popup above is the notice. If the popup is dismissed, the paused-reason line explains the state |
| Prompt Inspector enabled while queue has items (SAFE-03, pause) | `toastr.warning`: `Queue paused: Prompt Inspector is on. Turn it off, then resume.` |
| Queue start attempted while Prompt Inspector is enabled (SAFE-03, refuse) | `toastr.warning`: `Can't start the queue while Prompt Inspector is on. Turn it off, then try again.` Fired from the control click, the wand "Queue swipe" entry, `/queueswipe`, and Resume. Items are **not** added |
| Second tab opens a chat whose queue another tab owns (SAFE-04) | `toastr.info`: `This chat's queue is managed in another tab. Showing it read-only here.` Once per chat load in that tab |
| Read-only tab becomes owner (owner tab closed) | `toastr.info`: `This tab now manages the queue. It is paused; resume from the queue badge.` |
| Native Stop pressed (GUARD-06) | No toast. Native Stop ends the user's own generation; queued items are untouched and the queue resumes as it does after any native generation. Queue cancel keeps Phase 3's coalesced `cancelled` reporting |
| Native send/swipe/continue starts mid-queue (GUARD-01) | No toast. This is a transient native pause, shown only through the dropdown status line |

### State labels (paused / read-only)

| Element | Copy |
|---------|------|
| Dropdown status line, paused (`.qs-dropdown-status`) | `Paused: {reason}` (see the reason table below) |
| Dropdown status line, native wait | `Waiting for your generation to finish` |
| Dropdown status line, read-only | `Managed in another tab` |
| Progress-bar label, paused | `Paused · {completed} / {total}` |
| Progress-bar label, read-only | `{completed} / {total}` (unchanged format; read-only is shown by the missing controls and the badge lock icon) |
| Control tooltip, read-only tab | `Queue is managed in another tab` |
| Control tooltip, Prompt Inspector on | `Turn off Prompt Inspector to queue swipes` |
| Badge tooltip, paused | `Queue paused ({reason})` |

Paused-reason labels (`{reason}`), as static literals selected by a reason code:

| Code | Label |
|------|-------|
| `restored` | `restored after reload` (PERS-02/03, including popup dismissal) |
| `failures` | `{n} failures in a row` |
| `connection` | `connection changed` |
| `inspector` | `Prompt Inspector is on` |
| `takeover` | `taken over from another tab` |

### Inherited (unchanged) copy

| Element | Copy |
|---------|------|
| Empty state | Not applicable, unchanged from Phase 3. Badge, dropdown and progress bar are hidden at 0 items, and the resume popup never appears for 0 valid items |
| Error state | Phase 3 coalesced summary, unchanged. A SAFE-01 pause does **not** suppress the coalesced summary for items that already finished; the pause toast is shown in addition, once |
| Destructive confirmation | **Discard queue**: confirmed by the resume popup itself (Copywriting above). Every other cancel surface keeps Phase 3's rule of no confirmation. No new confirmation dialog is added for Cancel all, ×, Stop or `/queuecancel` |

### Notification-style interaction (D-09)

The Phase 3 "Notification style" setting (`All` / `Errors only` / `Off`) continues to govern **only** the coalesced completion and failure summaries. All lifecycle, pause and safety toasts in this phase are always shown, at every notification style, because each one explains a state change the user must know about to avoid lost work or surprise spend. Every new toast passes `{ preventDuplicates: true }`.

## Interaction Contract (phase-specific)

### Queue states shown by the UI

| State | Badge | Dropdown | Progress bar | Control |
|-------|-------|----------|--------------|---------|
| Running (Phase 3) | spinner + count | rows + Cancel running + Cancel all | fill + `c / t` + Stop | normal |
| Waiting for native generation (GUARD-01) | count (no spinner unless an in-flight item is still generating) | status line `Waiting for your generation to finish` + Phase 3 buttons | unchanged | normal |
| Paused (`restored` / `failures` / `connection` / `inspector` / `takeover`) | `fa-pause` + count, tooltip `Queue paused ({reason})` | status line `Paused: {reason}`, **Resume queue** button (neutral) above Cancel all; rows keep their per-item × | `.qs-progress-bar--paused`: label `Paused · c / t`, fill at 50% opacity, **Resume** (`fa-play`, tooltip `Resume queue`) to the left of Stop | normal (adding to a paused queue is allowed and does not resume it) |
| Read-only, second tab (SAFE-04) | `fa-lock` + count (spinner instead of lock while the owner is generating is **not** shown; lock always wins) | status line `Managed in another tab`; rows have **no** ×; **no** Cancel running, Cancel all or Resume buttons | label `c / t`, **no** Stop and **no** Resume button | `.qs-queue-control--disabled`, tooltip `Queue is managed in another tab`; clicks no-op |
| Prompt Inspector on (queue empty or paused with reason `inspector`) | hidden when empty; otherwise as Paused row | n/a when empty; otherwise as Paused row | hidden when empty; otherwise as Paused row | `.qs-queue-control--disabled`, tooltip `Turn off Prompt Inspector to queue swipes`; click fires the refuse toast. This overrides the Paused row's "normal" control |

**Accessible names:** `.qs-progress-bar-resume` gets `title="Resume queue"` and `aria-label="Resume queue"`. The badge's `aria-label` matches its tooltip (`Queue paused ({reason})` or `Queue is managed in another tab`). Follow the same pattern as the Phase 3 Stop and × controls.

### Resume / discard popup (PERS-02, PERS-03)

| Rule | Detail |
|------|--------|
| When | After `CHAT_CHANGED` (which also fires on the initial load after a refresh) for a chat whose `chat_metadata` holds at least 1 valid stored item, after stale items were dropped (PERS-04 toast first) |
| Never | In a read-only tab; when 0 valid items remain; while a native generation is running (defer until idle); more than once per chat load |
| Initial state | The queue is paused with reason `restored` **before** the popup opens. Nothing runs while the popup is open |
| API | `callGenericPopup(content, POPUP_TYPE.CONFIRM, '', { okButton: 'Resume queue', cancelButton: 'Discard queue' })`. Content is built as DOM nodes (`<h3>` title + `<p>` lines) via `textContent`. Verify live in ST 1.19.0 that Esc/close resolves to a value distinct from the Cancel button (expected `POPUP_RESULT.CANCELLED` vs `POPUP_RESULT.NEGATIVE`); if they cannot be told apart, treat both as **Keep paused**, never Discard |
| OK | Clears the `restored` pause and calls `runner.resume()` |
| Cancel button | Removes all stored items for this chat, saves via `saveMetadataDebounced`, shows the discard toast |
| Esc / close | Stays paused with reason `restored`. Items stay stored |
| Model line | Uses the api/model/preset recorded on the item at queue time (ids, names and timestamps only; no prompts, per PERS-01). If the items have mixed values, show the oldest item's |

### Connection-changed popup (SAFE-02)

| Rule | Detail |
|------|--------|
| When | Immediately before the runner would start the next item, if the current api, model or preset differs from the value recorded on that item. The check runs per item, not only on load |
| State | The queue pauses with reason `connection` before the popup opens. The running item (if any) is not aborted |
| OK `Continue queue` | Updates the recorded connection on all remaining items to the current values (so the popup does not reappear for each one) and resumes |
| Cancel / Esc `Keep paused` | Stays paused with reason `connection`. Pressing Resume later re-runs the same check and shows the popup again if the connection still differs |
| Merged | On load, this is merged into the resume popup (Copywriting, "Combined case"); never two popups back to back |

### Circuit breaker (SAFE-01)

| Rule | Detail |
|------|--------|
| Threshold | Read live from `extension_settings[MODULE_NAME].circuitBreakerThreshold` (Phase 3 input, range 1–10). Default stays **3** as shipped in Phase 3 (D-10). REQUIREMENTS.md SAFE-01 says "default 2"; the planner must reconcile this one value and must not add a second setting |
| Counts | `api` and `empty` failures. `cancelled` (user cancel) and `stale` never count; a success resets the counter to 0 |
| On trip | Pause with reason `failures`, show the SAFE-01 toast once, no retry. Remaining items stay queued |
| Resume | Resets the counter to 0 |

### Prompt Inspector (SAFE-03)

| Rule | Detail |
|------|--------|
| Refuse | Every add path (control, wand, `/queueswipe`) and Resume checks Prompt Inspector first; if it is on, show the refuse toast and do nothing else |
| Pause | If it turns on while items are queued, the queue pauses with reason `inspector` after the current item finishes (the in-flight item is not aborted) |
| After it turns off | No auto-resume. The user presses Resume, the same as every non-native pause. Only the native-generation wait (GUARD-01) resumes automatically |

### Resume button behavior (all paused reasons)

| Surface | Behavior |
|---------|----------|
| Dropdown `Resume queue`, progress-bar `fa-play` | The same single action: re-run the SAFE-03 check (refuse toast if Inspector is on) and the SAFE-02 check (popup if the connection differs), then clear the pause and call `runner.resume()` |
| Wand menu | No new entry. Resume is available from the badge and the progress bar only |
| Slash command | No new command. `/queuestatus` text gains a paused suffix: `Queue: {running} running, {pending} pending ({max} max), paused ({reason}).` The read-only form is `Queue: {running} running, {pending} pending ({max} max), managed in another tab.` |

### Multi-tab read-only (SAFE-04)

| Rule | Detail |
|------|--------|
| Owner | One tab owns a chat's queue. The others render the read-only row of the state table |
| Read-only display | The count, spinner/lock and `c / t` update live from the owner's state. Read-only tabs never write `chat_metadata` for the queue |
| Slash commands in a read-only tab | `/queueswipe` and `/queuecancel` toast `This chat's queue is managed in another tab.` (`toastr.warning`) and change nothing; `/queuestatus` works and returns the read-only status form |
| Takeover | When the owner tab goes away, a read-only tab becomes owner in the paused state (`takeover`) and shows the takeover toast. It does **not** open the resume popup and does not auto-run |

### Lifecycle clears (GUARD-02, GUARD-03)

| Trigger | UI effect |
|---------|-----------|
| Edit, delete, new message | Items are removed and the store notifies; badge, dropdown and progress bar re-render through the existing `store.onChange` path (they hide at 0). Then exactly one GUARD-02 toast is shown. Cleared items do **not** go into the Phase 3 coalesced failure summary, because the GUARD-02 toast already reports them |
| Chat switch | The badge and progress bar for the old chat disappear with the chat. The aborted running item is not counted in any summary or failure toast |
