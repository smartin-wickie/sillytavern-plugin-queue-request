<objective>
## Phase Goal

**As a** SillyTavern user, **I want** the queue to stop itself when requests keep failing or when Prompt Inspector is on, **so that** a bad connection or a conflicting extension can never burn through my API credits.

Purpose: SAFE-01 (circuit breaker, D-11 default 3, D-12 in-memory counter) and SAFE-03 (refuse/pause while Prompt Inspector is enabled). Extracts the shared `enqueue` helper first so the Prompt Inspector refusal lives in one place instead of three drifting copies.
Output: breaker and inspector gate in the runner, bridge probe, shared enqueue/resume gates, toasts, disabled control state, tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user settings to runner | circuitBreakerThreshold is user-editable |
| localStorage flag / other extension | Prompt Inspector toggle is read from a flag any script can write |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-20 | Elevation (spend) | runaway failing requests | mitigate | Breaker pauses after N api/empty failures; no retry code path; threshold clamped 1..10 with fallback 3 |
| T-04-21 | Tampering | bad threshold value disables the breaker | mitigate | Clamp and non-finite fallback in the runner, not only in the settings UI |
| T-04-22 | Spoofing | forged promptInspectorEnabled flag | accept | Worst case is a refused/paused queue (DoS on self); presence check avoids permanent refusal after uninstall |
| T-04-23 | Elevation | Resume bypassing the inspector gate | mitigate | resumeQueue checks inspector, and processNext gate re-pauses regardless of how it was resumed |
| T-04-24 | Tampering (XSS) | toast text | mitigate | Static literals plus integer n only |
</threat_model>
