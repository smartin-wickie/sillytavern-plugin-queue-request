<objective>
Ship the SET-01 settings panel in the Extensions drawer, and make all 5 fields actually take effect live — not just display a value. Two of the five (notification style, circuit-breaker threshold-as-a-stored-number) already have a live consumer somewhere in this phase (`src/ui.js`'s `getNotificationStyle()` from 03-03; circuit-breaker enforcement itself is explicitly Phase 4's GUARD-06, this phase only stores the value per D-10). "Max queue size" is a third case that looks already wired but is not: `store.js`'s `effectiveCap()`/`getMaxQueueSize()` always compute live off the `maxQueueSize` value, but that value is only ever set once, as a `createStore({ maxQueueSize })` constructor parameter at `index.js`'s `init()` time — nothing updates it afterward, so writing a new value to `extension_settings[MODULE_NAME].maxQueueSize` alone would leave the running store enforcing whatever cap was configured at extension activation (default 5) until a full page reload, directly contradicting D-12 ("All settings panel values take effect live, no reload required") and ROADMAP Phase 3 success criterion 4. This plan closes that gap by adding a `store.setMaxQueueSize(n)` mutator and having the settings handler call it. The remaining two fields — "Enable queued swipes" and "Jump to newest swipe on completion" — have no consumer anywhere in the codebase yet, so this plan wires them too: `enabled` gates the existing `canQueue()` visibility check (reused by the control, the wand entry, and `/queueswipe`), and `autoJump` adds the conditional "jump to the new swipe" behavior `ARCHITECTURE.md` §1.5/§2.2 already specified but Phase 2 deliberately left unimplemented (confirmed in `02-VERIFICATION.md`: "no auto-jump implemented this phase").

Purpose: Satisfy ROADMAP Phase 3 success criterion 4 ("the values take effect") for every field the panel exposes, not just the ones that happened to already have a consumer.
Output: `settings.html` (new), `src/settings.js` (new), `index.js` (DEFAULT_SETTINGS extended, MODULE_NAME centralized, store passed into registerSettingsPanel), `src/st-bridge.js` (enabled gate in canQueue), `src/appender.js` (conditional auto-jump), `src/commands.js` (enabled gate in /queueswipe), `src/store.js` (setMaxQueueSize mutator so Max queue size takes effect live), `test/store.test.js` (coverage for setMaxQueueSize).

|----------|--------------|
| Settings panel `<input>`/`<select>` DOM ↔ `extension_settings[MODULE_NAME]` | User-entered numeric values are the only untrusted input this plan writes to persisted state |
| `src/appender.js` ↔ ST's `swipe.to()` API | The auto-jump call must only ever go through this public API, never a direct chat-array mutation |
| `src/settings.js` ↔ `src/store.js` (in-memory, same-process) | The `setMaxQueueSize()` call crosses a module boundary but not a trust boundary — both sides run in the same browser tab under the same user's session |
